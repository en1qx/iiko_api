# iiko API

Небольшая панель для вызова нужных методов iiko Transport, Яндекс Еды и Магнита из браузера.

- Секрет iiko остаётся в Docker-контейнере.
- Токены и ответы живут только в памяти вкладки браузера и пропадают после обновления страницы.
- Сохранённые API-логины хранятся только в `localStorage` браузера; на сервер они не записываются.
- В базе данных, очередях и сторонних пакетах приложение не нуждается.

## Запуск

На сервере создай отдельный каталог, например `/opt/docker/iiko-api`, и скопируй туда содержимое этого проекта.

Создай файл `.env` рядом с `docker-compose.yml` на основе `.env.example`:

```env
IIKO_APP_ID=09f4de98-3d5a-40e6-b274-914e58af54d1
IIKO_CLIENT_SECRET=ваш_clientSecret
PORT=3000
```

Затем запусти:

```bash
docker compose up -d --build
```

Проверка локально на сервере:

```bash
curl http://127.0.0.1:3000
```

## Nginx Proxy Manager

Создай Proxy Host для нужного поддомена и направь его на IP сервера и порт `3000`. Включать WebSocket не требуется. HTTPS и Access List настрой по своему обычному шаблону.

Если NPM находится в той же Docker-сети и не хочется открывать порт наружу, можно убрать `ports` из compose-файла и добавить сервис в общую сеть NPM; тогда в Proxy Host укажи имя контейнера `iiko-api-panel` и порт `3000`.

## Что есть в интерфейсе

- **Transport:** v2-авторизация, организации, терминальные группы, оплаты, скидки, внешние меню и их состав, номенклатура, стоп-листы, программа лояльности iikoCard.
- **Яндекс Еда:** OAuth, заведения, состав меню, availability/стоп-лист, акции меню, заказ по ID. Адрес интеграции и реквизиты вводятся для текущего сеанса.
- **Магнит:** OAuth, заведения, меню, стоп-лист, заказ по ID и создание заказа. Адрес из коллекции заполнен заранее, но его можно изменить.

Для Яндекса и Магнита поддерживаются только HTTPS-адреса поддоменов `*.iikoweb.ru` — это защита от случайной отправки реквизитов на посторонний адрес.
